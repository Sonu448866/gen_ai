Prompt Chaining is a technique in which the output of one LLM prompt is passed as the input to another LLM prompt to complete a complex task through multiple smaller steps.

Instead of asking an LLM to perform everything in one prompt, we divide the task into multiple stages.

Think of it like a pipeline:
1.LLM generates an initial answer.
2.Generated content is passed forward.
3.LLM checks grammar and improves clarity.
4.Improved content.
5.LLM creates a concise final version.
6.Final Answer

PROMPT CHAINING VS ReAct
Prompt Chaining and ReAct both involve multiple steps, but they solve different problems.

The key difference is:

- Prompt Chaining: We decide the sequence of steps beforehand.
- ReAct: The LLM decides what to do next based on its current observations and reasoning.
  Let's understand why we need both.

1. Prompt Chaining
   Prompt chaining means breaking a complex task into smaller prompts, where the output of one prompt becomes the input of the next prompt.

Example: Generating a technical blog
Prompt 1: Generate an outline

Input: Topic = Java Collections

Prompt 2: Write the content

Input: Outline generated by Prompt 1

Prompt 3: Review and correct

Input: Blog generated by Prompt 2

Final output: Published blog

2. ReAct (Reason + Act)
   ReAct is different because the LLM dynamically decides which action to perform based on its observations.

Suppose you ask:

"Find the current price of an iPhone and compare it with its previous price."

The agent might perform these steps:

User query: Find current and previous price.

Thought: I need to find the current price first.

Action: Search web

Observation :Current price found. Now I need the previous price.

Action: Search historical price

Final answer: Compare both prices

The important thing is that the next action depends on the observation.

If the current price is unavailable, the agent might try another website instead.

That's the flexibility of ReAct.

Parameter Prompt Chaining ReAct

Workflow Predetermined Dynamic
Next step Already defined Decided by LLM
Tool usage Not necessary Commonly used
Decision-making Limited Dynamic
Predictability High Lower
Complexity Relatively simple Relatively complex
Best for Structured workflows Autonomous tasks

Consider these examples:

Scenario A: Resume generation

1. Extract skills.
2. Identify relevant projects.
3. Generate resume.
4. Review grammar.
   Prompt chaining is sufficient because the workflow is predictable.

Scenario B: Travel planning

1. Search flights.
2. Check hotel availability.
3. Compare prices.
4. If flights are expensive, explore alternative dates.
5. If hotels are unavailable, search nearby locations.
   ReAct is useful because the next action depends on the results.

The main advantage of prompt chaining over React is that debugging is easy in prompt chaining as we can view the output of each prompt and based on that we can rectify it but in case of ReAct we can't do that as whole prompt is given as input.
Also there is modularity in prompt chaining.
Also if out of all tasks some taks are complex and rest are easy then you can delegate the complex tasks to better models and easy one to smaller model and hence reducing the total cost.
